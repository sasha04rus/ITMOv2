# Правила для агента и команды (Практика 4)

Цель: реализуем две функции в сервисе подписок без HTTP-слоёв:

- A: `unsubscribe(name)` — удалить подписчика.
- B: `list_subscribers()` — вернуть список подписчиков.

Общие правила:

- Любые изменения в `practices/practice_04/service/` проходят через runner; результаты автозапуска попадают в `.opencode/hooks/results/latest.json` и доступны агенту.
- Перед сохранением правок проверяйте имя подписчика MCP-инструментом `validate_subscriber_name` (обрезка пробелов; пустые имена запрещены).
- Следуйте простым тестам (минимальные unit-тесты), формат не жёсткий, но добавляйте кейсы на повторную отписку и пустые имена.
- В рамках практики 4 не добавляем HTTP-эндпоинтов, генераторов приложения и пагинации.

Требуемые подключения:

- Skill `add-subscriptions-feature` подсказывает порядок шаго́в (валидация имени через MCP, запуск runner) и применяется к изменениям сервиса.
- MCP сервер `validate_subscriber_name` — стандартизированный инструмент валидации имени через stdio.
- Плагин-хук запускает runner после правок и публикует результат в контекст (см. plugin runner). Повторные срабатывания из-за собственных логов исключены.

Короткие подтверждения:

- Загрузка skill — через `opencode debug skill` (видно `add-subscriptions-feature`).
- MCP — два вызова (успех и ошибка), видны в `evidence/mcp_calls.log`.
- Автопроверка — запуск runner после правки; краткий итог в `evidence/runner_auto.log` и `results/latest.json`.
