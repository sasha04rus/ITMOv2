# Критическая проверка LLM-судьи

Судья — `ollama/itmo-agent` в отдельных новых сессиях `threat-judge`, tools deny.
Системный prompt одинаковый, его SHA находится в model.json. Та же модель
использовалась для planner, поэтому независим контекст сессии, а не веса модели;
это ограничение, а не замена человеческого анализа.

## Сохранённые попытки

| Попытка | Результат | Как использован |
|---|---|---|
| before/judge | Непустой JSON с verdict unsafe | Сверен с исходником и HTTP-фактами |
| after/judge | Пустой видимый ответ; finish reason length, output4096 | Не считается успешной проверкой; сохранён без редактирования |
| after/judge-retry | Непустой ответ, текст verdict improved и три риска | Проверен отдельно; исходный ответ не исправлялся |

У retry после закрывающей фигурной скобки есть лишний backtick. Поэтому весь
ответ нельзя считать валидным JSON заданной схемы. Он используется как текст
предложений проверяющего, а не как машинное подтверждение безопасности.

В retry сохранён полный текущий service.py и факты всех29 HTTP-проверок; убраны
дублирующие полные отчёты и длинная модель угроз. Полная матрица F-ID в этот
компактный вход не включалась, поэтому F01/F02/F03 в ответе нельзя автоматически
сопоставлять с нашим реестром: сравниваются смысл, маршруты и проверяемые условия.
Это ограничение самого пакета входных данных, а не доказанная ошибка модели.

## Проверка before-ответа

- SQLi, подмена X-Role, цена из тела клиента и unsafe HTML подтверждаются кодом
  и HTTP-проверками; эти замечания приняты.
- «Full traceback» не соответствует исходнику: наружу уходили str(exception)
  и имя типа, а не полный стек. Утечка деталей реальна, формулировка уточнена.
- S19 подтверждает сохранение отзыва (201). Неэкранированный HTML подтверждает
  S20; ссылка только на S19 недостаточна для вывода об исполнении скрипта.
- Успешное удаление вследствие prompt injection не подтверждено. Before poisoned
  ответ содержал неверный аргумент filePath, а forced delete был отдельным тестом.
- Поля severity/limitations не во всём соответствуют запрошенной схеме;
  структурированный формат ответа сам по себе также требует проверки.

## Проверка трёх after-подозрений

Все три проверены отдельным `lab/test_judge_claims.py`, фактический вывод —
`evidence/after/judge-claims-tests.txt`: **3 tests OK**.

| Подозрение судьи | Проверка по коду и факту | Вывод |
|---|---|---|
| R01: неполное тело HTTP может исполнить опасное решение | В реальный socket отправлен синтаксически валидный delete_tree JSON с Content-Length больше фактического тела, затем half-close. Сервер вернул400 incomplete body, три файла сохранились. В handler есть len(data)==size до json.loads. | Заявленный обход не воспроизведён; проверка уже присутствует |
| R02: html.escape может пропустить nested entities/quotes | Реальный отзыв с img/onerror, кавычками и строкой &lt;script&gt; отображается через html.escape(..., quote=True); активного img-тега нет. Дополнительно проверены CSP default-src none и nosniff. | Для проверенного text-in-p контекста предположение не подтвердилось; полный браузерный XSS-аудит не заявляется |
| R03: monotonic подвержен переводу системных часов, TTL надо проверять на входе | session() уже вызывается в начале каждого dispatch. При контролируемом продвижении monotonic за SESSION_TTL токен даёт401, до истечения200. ОС-часы не менялись, использован unittest.mock. | Проверка истечения есть; объяснение про перевод wall clock неверно |

Семантика monotonic: часы не идут назад и не зависят от перевода системного
времени — [документация Python](https://docs.python.org/3/library/time.html#time.monotonic).
Экранирование &, <, > и кавычек при quote=True описано в
[html.escape](https://docs.python.org/3/library/html.html#html.escape).
Эти ссылки обосновывают конкретные свойства API, а не отсутствие любых уязвимостей.

В конце retry судья назвал status403 «successful bypasses». Это неверная
интерпретация: в наших проверках403 обозначает отказ в доступе, а реальный
обход подтверждался бы получением запрещённых данных или выполнением действия.

## Итоговая оценка

Вердикт improved согласуется с дифференциальными HTTP-фактами и тестами, но не
служит доказательством. Неподтверждённые замечания не исправлялись вслепую:
сначала проверены существующий код и конкретные входы. Дополнительные3 проверки
включены в окончательные make step6/make test — теперь **36 тестов магазина**.

Остаточные ограничения сохраняются: публичные учебные credentials, локальный
stdlib-сервер, in-memory/static fixtures, отсутствие production IAM/TLS,
неполный DoS/нагрузочный/браузерный аудит и отсутствие гарантий для других LLM.
