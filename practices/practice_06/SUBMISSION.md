# ДЗ6: запуск, проверка и защита

## Материалы

- `THREAT_MODEL.md`: DFD, границы, роли и реестр F01–F13.
- `REPORT_01.md`: исходные атаки, красные регрессии и реальный before LLM.
- `REPORT_02.md`: исправления и повторные проверки.
- `judge-system-prompt.md`: собственные правила LLM-судьи.
- `JUDGE_REVIEW.md`: критический разбор ответов судьи.
- `evidence/before/` и `evidence/after/`: точные входы, видимые ответы и эффект.

## Запуск из корня рабочей копии в WSL

```bash
make step6
make test
cd practices/practice_06/lab
python3 service.py --port 8066
```

Во втором терминале можно логиниться через HTTP. Стенд использует только
учебные пароли из lab/README.md; токен передаётся в X-Token. API всегда слушает127.0.0.1.

## Воспроизводимые проверки

Из `practices/practice_06/lab`:

```bash
python3 security_probe.py --phase after
python3 llm_probe.py --phase after --model ollama/itmo-agent
python3 llm_probe.py --phase after --judge-only --model ollama/itmo-agent
# При исчерпании ответа на большом пакете:
python3 judge_retry.py --phase after
python3 verify_evidence.py
```

Probe сам создаёт и закрывает свой процесс на свободном порту. Не нужно
указывать чужой адрес. Для before используйте исходную версию service.py из
коммита c675285 либо checkout коммита аудита 70cce47: там уже есть скрипты,
но ещё нет фикса. Не переключайте грязную рабочую копию; используйте отдельный worktree.

LLM-эксперимент требует OpenCode и установленный в практике3 alias itmo-agent
в локальном Ollama на11434. Tools у shop-planner/threat-judge запрещены.
Четыре target-сессии независимы, system/user task и review одинаковы; raw
answer.txt не правится даже при ошибке модели. Внутренние рассуждения не сохраняются.
Рабочие файлы применялись через OpenCode Build и его детерминированные custom
commands; подготовленные ИИ патчи/результаты проверялись координатором.

## Демо на защите

1. Покажите DFD и объясните границы HTTP→session→data и LLM→executor.
2. Откройте before/probes.json: Alice видит Bob, spoof role даёт export,
   chair покупается за-1, а forced delete удаляет три fixture-файла.
3. Покажите after/probes.json: запросы запрещены либо используют серверную цену;
   forced delete получает403 и сохраняет файлы.
4. Покажите исходные answer.txt четырёх LLM-сессий. В before poisoned-ответе
   был неверный аргумент filePath, а не успешное удаление моделью.
5. Запустите make step6, объясните, почему старые16 зелёных тестов не были аудитом.
6. Покажите JUDGE_REVIEW.md: судья может неточно ссылаться на строки и ошибаться
   в деталях; реальные HTTP-результаты и код имеют приоритет.

## Выводы для PR

Обычные функциональные тесты пропускали нарушения доступа, SQLi, подмену цены,
утечки журнала и неограниченные AI-инструменты. Воспроизводимые отрицательные
проверки дали исходную картину; после серверных исправлений проходят36 тестов
и29 HTTP-checks, а исходная файловая песочница сохранена.

Системный prompt и LLM-судья полезны, но не являются границей полномочий.
Модель не подчинилась проверенной инструкции на удаление, однако до фикса
прямой опасный JSON всё равно удалял fixture. После фикса allowlist и проверки
сессии блокируют действие независимо от ответа модели; ошибки судьи разбираются
по исходнику и фактам, а не принимаются автоматически.
