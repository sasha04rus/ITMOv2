# Конституция сервиса подписок

Версия 1.0.0. Принята для практики 5: 2026-10-26.

1. **Спецификация до реализации.** UI и логика имеют независимые исходные
   спецификации и один общий контракт. Разногласия записываются; изменение
   поведения согласуется человеком до написания соответствующего кода.
2. **Совместимость.** Исходные subscribe/unsubscribe/list_subscribers сохраняют
   поведение. Поиск — операция чтения; БД и HTTP CRUD не добавляются.
3. **Минимальный стек.** Приложение работает на Python 3.10+ standard library и
   обычных HTML/CSS/JavaScript. Spec Kit и браузерные тесты — инструменты
   разработки, не зависимости запуска сервиса.
4. **Проверяемое поведение.** Проверки покрывают основной, ошибочный, граничный
   и прежний сценарии. Авторский отчёт не заменяет запуск тестов; результат
   сверяется со спецификацией отдельным проверяющим агентом.
5. **Честные подтверждения.** Сохраняются исходные спеки, решение человека,
   результаты команд и реальное демо. Прохождение CLI-проверки структуры не
   означает правильность приложения. Имена и сообщения выводятся в UI как текст.

Изменение границ требует синхронизации контракта, обеих спецификаций и тестов.
