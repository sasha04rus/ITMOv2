## Результат

В существующий Python-сервис подписок добавлен read-only веб-поиск. Работают
поиск подстроки без учёта регистра, русский текст, пустой результат, сброс,
ошибки и повтор запроса. Прежние функции подписки, отписки и списка сохранены.

Стек приложения: Python standard library и HTML/CSS/JavaScript без сборки.
Хранилище — set в памяти; `--demo` явно добавляет Alice, Bob, Анна, Борис.

## SDD и две команды

Применён GitHub Spec Kit `1.2.4.dev0` из официального исходного кода,
закреплённого SHA `9783b49ed66c26935cf7ef5ccc6ae5a296316eb7`.
CLI реально установлен и инициализирован внутри этой практики; официальные
скрипты создания feature, плана и подготовки задач выполнены. Их результаты
сохранены в `evidence/spec-kit-cli.json` и `spec-kit-bootstrap.json`.
Сравнение с OpenSpec — `FRAMEWORK.md`.

Две независимые агентные сессии сначала подготовили UI- и logic-спецификации,
не читая черновик другой команды. Исходные версии находятся в `specs/before/`.
После чтения обеих версий подготовлены общий контракт и `specs/after/`.

Содержательные решения:

- В UI был лимит 100, в логике — 128. Принят единый серверный лимит **100 Unicode
  code points после strip**, включая символы вне BMP.
- Для превышения длины выбран `query_too_long`; для неоднозначных параметров —
  `invalid_query`. UI и сервер больше не ожидают разные коды одной ошибки.
- `total` — количество совпадений, равное длине `items`, а не размер всего каталога.
- Пустой запрос возвращает всех, отсутствие совпадений даёт 200, а не ошибку.
- Unicode-нормализацию выполняет сервер; UI не дублирует её JavaScript trim/maxlength.

Пользователь утвердил конкретный контракт ответом «Утверждаю, реализуй» до
реализации. Решение и хеши исходных спецификаций — `evidence/human-approval.json`.
Отдельный коммит **684c057** содержит спецификации и настройки до появления
приложения и feature-тестов. Это подтверждает порядок, а не только итоговый текст.
Итоговую оценку и приёмку готового результата агент за пользователя не заявляет.

## Сквозной сценарий: ожидание → факт → доказательство

| Сценарий | Ожидание | Факт |
|---|---|---|
| Открытие страницы | UI получает четыре отсортированных имени из реального API | Пройдено, сохранён desktop.png |
| `  ALI  ` | Запрос нормализуется на сервере; только Alice, total=1 | HTTP 200 и полный JSON сверены браузерным тестом |
| `АН` через Enter | Только Анна, исходное написание | Пройдено через настоящий UI/API |
| Нет совпадений | 200, пустой список и «Ничего не найдено» | Пройдено |
| Сброс | Полный список, пустое поле и фокус в нём | Пройдено |
| 100/101 emoji | 100 принимаются, 101 даёт 400 query_too_long | Пройдено через UI и реальный API, сохранён query-error.png |
| Потеря сети и повтор | Ошибка, затем повтор последнего отправленного запроса | Пройдено с управляемым сетевым сбоем |
| Неверная JSON-форма | Общая ошибка, повтор восстанавливает результат | Пройдено с подменённым ответом |
| Старый ответ | Не перезаписывает новый поиск | Пройдено с задержкой старого запроса |
| HTML-подобное имя | Выводится текстом, HTML не исполняется | Пройдено с подменённым ответом |
| Мобильный экран | Нет горизонтального переполнения | Пройдено, сохранён mobile.png |

Первые шесть сценариев проходят реальную цепочку UI → HTTP → сервис → UI.
Сетевой сбой, некорректный ответ, задержка и HTML-подобное имя намеренно
контролируются браузерным тестом; они не выдаются за сбои настоящего backend.
Точные типы сценариев помечены в e2e.json.

## Ограничения

- Локальное учебное приложение: без БД, персистентности и авторизации.
- Линейный поиск и обычный Python sorted предназначены для небольшого списка.
- Нет транслитерации, исправления опечаток, NFC-нормализации и е/ё-эквивалентности.
- Браузерные сценарии проверены в Edge; другие браузеры и screen reader отдельно
  не проверялись. Проверка структуры Spec Kit не доказывает правильность UI/API.

Команды запуска и короткий сценарий демо находятся в README.md.
