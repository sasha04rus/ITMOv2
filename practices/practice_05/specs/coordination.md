# Согласование двух команд до реализации

Дата: 2026-10-26. Реализация фичи на этом этапе не создавалась.

## Происхождение исходных спецификаций

- `/root/practice05_ui` независимо подготовил `before/ui.md`, не читая логику.
- `/root/practice05_logic` независимо подготовил `before/logic.md`, не читая UI.
- Это две отдельные агентные сессии в одном задании, а не утверждение о двух
  реальных организациях или разработчиках. Пользователь разрешил этот способ.
- Исходные файлы сохраняются без редактирования; исправления идут в `after/`.

## Обнаруженные расхождения и предложенные решения

| Вопрос | Команда UI | Команда логики | Предлагаемое решение |
|---|---|---|---|
| Длина запроса | 100 code points | 128 символов | 100 code points после серверного `strip()`; UI не вводит другой лимит |
| Ошибка длины | query_too_long | Общая invalid_query | Для длины query_too_long, для структуры параметров invalid_query |
| Поле total | Число совпадений | Число совпадений, обсуждался total_all | Только число совпадений, равно items.length |
| Сортировка | Сохранять порядок backend | sorted по исходным именам | Сохраняем прежнюю сортировку сервиса |
| Неизвестный или повторный q | Открытый вопрос | Отклонять повторный, неизвестные обсудить | Отклоняем оба случая с 400 invalid_query |
| Наполнение | Открытый вопрос | Явный --demo | --demo с четырьмя именами, иначе пусто |
| Русские имена | Без учёта регистра | Unicode casefold | casefold, без е/ё-эквивалентности и транслитерации |

## Следующий этап

Обе команды сверяют обновлённые спецификации с `001-subscriber-search/contracts/http.md`.
Затем пользователь принимает или корректирует конкретный контракт. Только после
этого начинается реализация. Факт решения фиксируется отдельно; его нельзя
подменять утверждением агента о завершённом согласовании.
