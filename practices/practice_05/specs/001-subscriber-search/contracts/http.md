# Общий контракт: поиск подписчиков v1

Статус: утверждён пользователем 2026-10-26 до реализации.
Дата: 2026-10-26. Контракт — общий источник истины для спецификаций UI и логики.

## Область изменения

Одна страница поиска по существующему сервису подписок. Данные остаются в
памяти процесса. Старые `subscribe`, `unsubscribe`, `list_subscribers` сохраняют
поведение. Новые операции добавления/удаления через HTTP, БД, авторизация,
пагинация и автоматический поиск при каждом нажатии клавиши не добавляются.

## Запрос

`GET /api/subscribers?q=<URL-encoded query>`

- Допустим только один параметр `q`. Его можно опустить; `?q=` эквивалентен
  отсутствию параметра. Повторный `q` или неизвестный параметр — `400 invalid_query`.
- Сервер удаляет краевые пробельные символы по правилам Python `str.strip()`.
- После нормализации допустимо от 0 до 100 Unicode code points включительно.
  Лимит проверяет сервер; 101 символ — `400 query_too_long`.
- Пустой запрос возвращает всех подписчиков. Непустой ищется как подстрока имени
  через Unicode `casefold()`. Исходное написание имени сохраняется. `е` и `ё`
  различаются; транслитерации, нечёткого поиска и Unicode NFC-нормализации нет.
- Порядок совпадает с прежним `list_subscribers()`: Python `sorted` по исходным
  строкам. Поиск не меняет хранилище и возвращает новый список.

## Ответ 200

```json
{"query":"ali","items":["Alice"],"total":1}
```

`query` — применённый запрос после `strip`, с сохранением его регистра.
`items` — массив строк; `total` всегда равен длине `items`, а не числу всех
подписчиков до фильтрации. Пустой результат — `200`, `items: []`, `total: 0`.
Заголовок: `Content-Type: application/json; charset=utf-8`.

## Ошибки

```json
{"error":{"code":"query_too_long","message":"Поисковый запрос должен быть не длиннее 100 символов."}}
```

| HTTP | code | Ситуация |
|---|---|---|
| 400 | query_too_long | Нормализованный запрос длиннее 100 code points |
| 400 | invalid_query | Повторный/неизвестный параметр или некорректная UTF-8 query string |
| 404 | not_found | Неизвестный маршрут |
| 405 | method_not_allowed | POST/PUT/PATCH/DELETE к поисковому API |

Валидный JSON-результат ошибки инструмента не означает падение процесса сервера.
UI показывает `error.message` при 400 как текст. При сетевой ошибке, 5xx или
некорректной форме JSON — общее сообщение и кнопку «Повторить».

## UI-состояния и действия

- При открытии `/` загружается полный список.
- Кнопка «Найти» и Enter отправляют запрос; «Сбросить» очищает поле, возвращает
  фокус и загружает полный список.
- `loading`: старый список скрыт; `success`: имена и число совпадений;
  `empty`: «Ничего не найдено»; `error`: сообщение и повтор последнего запроса.
- Более старый ответ не может перезаписать новый. Список и сообщения выводятся
  через текстовые DOM-операции, без интерпретации HTML из API.
- Поле имеет label, кнопки работают с клавиатуры, статус объявляется через
  live region. UI не дублирует серверные правила длины и Unicode trim.

## Демонстрационные данные

Явный флаг запуска `--demo` добавляет `Alice`, `Bob`, `Анна`, `Борис` через
существующий `subscribe`. Без флага начальное хранилище пустое. Перезапуск
теряет изменения в памяти, а `--demo` заново создаёт демонстрационный набор.

## Критерии приёмки

1. Начальная загрузка и сброс показывают полный отсортированный список.
2. `  ALI  ` находит `Alice`, `АН` находит `Анна`; регистр исходных имён сохраняется.
3. Отсутствие совпадений даёт пустое состояние без ошибки.
4. 100 code points допустимы, 101 отклоняется; UI сообщает об ошибке и может
   восстановиться повтором или новым корректным запросом.
5. Старые операции проходят регрессионные тесты; поиск не меняет данные;
   сквозной браузерный сценарий подтверждает UI → API → логику → UI.
