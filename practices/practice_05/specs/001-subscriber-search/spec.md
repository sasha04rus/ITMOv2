## User Scenarios & Testing

### User Story 1 — найти подписчика (P1)

Пользователь хочет найти подписчика по части имени без учёта регистра, включая
русские имена, и видеть исходное написание найденных имён.

**Why this priority**: это основная ценность одной выбранной фичи.
**Independent Test**: сервер с `--demo`; поиск `  ALI  ` показывает Alice, `АН` — Анна.

**Acceptance Scenarios**:

1. **Given** четыре демонстрационных имени, **When** открывается страница,
   **Then** отображается полный отсортированный список и количество 4.
2. **Given** тот же набор, **When** выполняется поиск `  ALI  `,
   **Then** отображается только Alice, количество 1.
3. **Given** тот же набор, **When** выполняется поиск `АН`,
   **Then** отображается только Анна, исходный регистр сохраняется.

### User Story 2 — восстановить список и понять результат (P1)

Пользователь различает загрузку, найденные записи, отсутствие совпадений и сбой.

**Independent Test**: найти отсутствующее имя, затем нажать «Сбросить».

1. **Given** существующий список, **When** совпадений нет,
   **Then** показано «Ничего не найдено», а не ошибка.
2. **Given** применён фильтр, **When** нажат «Сбросить»,
   **Then** поле пустое, в фокусе, полный список снова загружен.
3. **Given** ошибка сети, **When** соединение восстановлено и нажат «Повторить»,
   **Then** повторяется последний отправленный запрос.

### Edge Cases

- Пустой запрос и строка из пробелов означают весь список.
- После серверного strip 100 Unicode code points допустимы, 101 — ошибка 400.
- Повторный q, неизвестный параметр и некорректный UTF-8 — invalid_query.
- Ответ на старый запрос не перезаписывает новый; текст имени не исполняется как HTML.
- Пустое начальное хранилище без --demo — корректное пустое состояние.

## Requirements

### Functional Requirements

- **FR-001**: UI MUST выполнять GET /api/subscribers и сохранять порядок API.
- **FR-002**: Логика MUST искать подстроку с Unicode casefold и сохранять имена.
- **FR-003**: Сервер MUST нормализовать запрос через str.strip и проверять лимит 100.
- **FR-004**: API MUST возвращать query, items и total=items.length либо JSON-ошибку.
- **FR-005**: UI MUST поддерживать loading/success/empty/error, сброс и повтор.
- **FR-006**: Поиск MUST оставлять хранилище и поведение старых функций неизменными.
- **FR-007**: Демо MUST включаться явно через --demo; данные остаются в памяти.

### Key Entities

- **Subscriber**: существующая строка имени; точные дубликаты исключает set.
- **SearchQuery**: строка после strip длиной 0–100 code points.
- **SearchResult**: query, новый массив имён items, целое total.
- **SearchError**: стабильный code и безопасное для вывода message.

## Success Criteria

- **SC-001**: Для набора Alice/Bob/Анна/Борис результаты начальной загрузки,
  латинского и русского поиска, пустого результата и сброса совпадают с контрактом.
- **SC-002**: Граница 100/101, неоднозначные параметры и прежние функции проходят тесты.
- **SC-003**: Реальный браузер подтверждает UI → HTTP → логику → UI и восстановление после ошибки.
- **SC-004**: Независимая проверка сопоставляет ожидание, факт и доказательство.

## Out of Scope

HTTP CRUD, БД, авторизация, пагинация, нечёткий поиск, транслитерация,
е/ё-эквивалентность и поиск при каждом вводимом символе.
