# Исходная спецификация команды логики: поиск подписчиков

Статус: независимый черновик до согласования с командой UI и человеком. Реализация и результаты тестов этим документом не заявляются.

## Исходный проект

Изучены `service.py` и `tests/test_service.py` сервиса практики 4 из ветки `codex/practice-04`.

- Хранилище `subscribers` представляет собой `set` в памяти процесса.
- `subscribe(name)` обрезает пробелы по краям, запрещает пустое имя и исключает точные дубликаты.
- `unsubscribe(name)` обрезает пробелы, запрещает пустое имя, возвращает `True` при удалении и `False` при отсутствии подписчика.
- `list_subscribers()` возвращает новый отсортированный список.
- В существующем наборе три теста: успешная/повторная отписка, пустое имя при отписке, сортировка списка.

Эти функции и их прежняя семантика сохраняются. Поиск не должен менять хранилище или вводить регистронезависимость при добавлении подписчиков.

## Цель и границы

Добавить чтение списка с фильтрацией по части имени для простой веб-страницы. Использовать Python standard library для HTTP и JSON, HTML/JS на том же origin. Новый backend-фреймворк, БД, авторизация, пагинация, изменение подписчиков через HTTP и персистентность не входят в задачу.

## Предлагаемые правила поиска

1. `search_subscribers(query)` принимает строку. Не-строка отклоняется как ошибочный вход.
2. Запрос нормализуется через `strip()`; внутренние пробелы сохраняются.
3. Поиск - подстрока: `query.casefold() in name.casefold()`. Это распространяется на латиницу и кириллицу.
4. Пустой запрос, включая строку из пробелов, возвращает весь список.
5. Ограничение - 128 символов Python `str` после `strip()`, включительно; это не лимит байтов UTF-8. Превышение отклоняется.
6. Имена в ответе сохраняют исходный регистр. Сортировка совпадает с существующим `list_subscribers()`, то есть `sorted` по исходным строкам, без локалезависимой сортировки.
7. Поиск возвращает новый список и не изменяет `subscribers`. Транслитерация, исправление опечаток, специальные правила для `е`/`ё` и Unicode-нормализация в эту версию не входят.

## Предлагаемый HTTP-контракт

### Успех

`GET /api/subscribers?q=<URL-encoded query>`

- `q` необязателен; отсутствие равно пустому запросу.
- `q` может присутствовать только один раз. Повторение считается неоднозначным ошибочным входом.
- В первой версии неизвестные параметры отклоняются, чтобы опечатка клиента не превратилась в незаметное изменение поведения.
- Ответ `200`, `Content-Type: application/json; charset=utf-8`.

```json
{
  "query": "ал",
  "items": ["Алексей"],
  "total": 1
}
```

`query` - нормализованный запрос; `items` - массив строк; `total` - количество совпадений, равное длине `items`, а не общее число подписчиков в хранилище.

Нет совпадений - обычный успешный ответ, например `{"query":"xyz","items":[],"total":0}`. Отсутствие подписчиков также не является ошибкой.

### Ошибки

```json
{
  "error": {
    "code": "invalid_query",
    "message": "Запрос должен содержать не более 128 символов."
  }
}
```

| Ситуация | HTTP | `error.code` |
|---|---:|---|
| Запрос длиннее лимита, повторный `q`, неизвестный параметр или некорректное кодирование | 400 | `invalid_query` |
| Неизвестный API-путь | 404 | `not_found` |
| Неподдерживаемый метод API | 405 | `method_not_allowed` |
| Неожиданная ошибка сервера | 500 | `internal_error` |

Для `405` сервер возвращает `Allow: GET`. Сообщение ошибки пригодно для отображения, но UI должен принимать решение по статусу и `code`, а не разбирать текст. Внутренние traceback клиенту не выдаются.

### Запуск и демонстрационные данные

- Сервер слушает `127.0.0.1`; предлагаемый порт по умолчанию - `8000`.
- `/` отдаёт страницу, API находится на том же origin, поэтому CORS-настройки не нужны.
- Без явного флага `--demo` хранилище пустое. `--demo` добавляет `Alice`, `Bob`, `Анна`, `Борис` через существующий `subscribe`.
- Флаг демонстрации не меняет HTTP-контракт и не включает сохранение данных. После остановки процесса данные теряются.

## Условия приёмки

1. Запрос без `q` и запрос из пробелов возвращают полный отсортированный список с неизменёнными именами.
2. Непустой запрос находит подстроку без учёта регистра в латинских и кириллических именах; отсутствие совпадений возвращает `200` с пустым `items`.
3. Граничная длина 128 символов принимается, 129 отклоняется с `400` и стабильным JSON-кодом `invalid_query`; повторный параметр не интерпретируется произвольно.
4. Поиск не меняет хранилище, а прежние сценарии `subscribe`, `unsubscribe` и `list_subscribers` продолжают работать.
5. Сервер с `--demo` позволяет UI выполнить сквозной сценарий поиска и ошибки; без флага демонстрационные подписчики не создаются.

## Проверяемые сценарии

| Тип | Given | When | Then |
|---|---|---|---|
| Основной | В хранилище Alice и Bob | GET с `q=ALI` | `200`, `items=["Alice"]`, `query="ALI"`, `total=1` |
| Кириллица | В хранилище Анна и Борис | GET с `q=АН` | `200`, `items=["Анна"]` |
| Нормализация | В хранилище Alice | GET с пробелами вокруг `ali` | Запрос обрезан до `ali`, Alice найдена |
| Пустой запрос | В хранилище несколько имён | `q` отсутствует или содержит только пробелы | Все имена в прежнем порядке сортировки |
| Нет совпадений | В хранилище Alice | GET с `q=zzz` | `200`, пустой массив, `total=0` |
| Ошибка/граница | Любое состояние | Длины 128 и 129 символов после trim | Первая принимается, вторая даёт `400 invalid_query` |
| Ошибка | Любое состояние | GET с `q=a&q=b` | `400 invalid_query` |
| Регрессия | Добавлен Alice | Поиск; затем отписка Alice дважды | Поиск не меняет set, отписка возвращает `True`, затем `False` |
| Изоляция | Получен список поиска | Вызывающий изменяет полученный список | Исходное множество не изменилось |
| Демо | Новый процесс | Запуск без флага / с `--demo` | Пустое хранилище / четыре ожидаемых имени |

## Вопросы для согласования

- Устраивает ли UI короткий параметр `q` и массив строк в `items`? Нужен ли отдельный счётчик всех подписчиков или достаточно количества совпадений?
- Согласован ли лимит 128 символов после trim и отсутствие локалезависимой сортировки?
- Нужен ли UI список всех подписчиков при пустом запросе? Предлагается именно это для начального экрана и сброса.
- Принимает ли UI правило «не найдено - 200 с пустым массивом», отделённое от HTTP/сетевой ошибки?
- Достаточны ли явные `--demo` и четыре имени для защиты без добавления CRUD-интерфейса?
- Оправдано ли отклонять неизвестные параметры, либо после обсуждения совместимости их лучше игнорировать?

## Компромиссы

Линейный поиск по множеству и сортировка подходят для учебного небольшого набора. Это не решение для большого каталога или многопользовательского редактирования. Нет БД и индексов; запуск без демонстрационного флага остаётся предсказуемо пустым.
