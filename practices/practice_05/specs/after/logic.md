**Дата:** 2026-10-26. **Источник истины:** `../001-subscriber-search/contracts/http.md`. Исходная независимая версия `../before/logic.md` сохранена без изменений.

## User Scenarios & Testing

### US-L1. Получить полный список или найти имя (P1)

Пользователь получает существующих подписчиков и ищет по части имени без учёта регистра. Имена сохраняют исходное написание и сортировку сервиса.

- **Given** существуют `Alice`, `Bob`, `Анна`, `Борис`, **When** API получает запрос без `q`, **Then** возвращаются все четыре имени в порядке Python `sorted` по исходным строкам.
- **Given** тот же набор, **When** `q` содержит `  ALI  `, **Then** ответ `200` содержит `query: "ALI"`, `items: ["Alice"]`, `total: 1`.
- **Given** тот же набор, **When** `q=АН`, **Then** найдена `Анна`.
- **Given** в запросе только краевые пробельные символы, **When** сервер применяет Python `str.strip()`, **Then** запрос становится пустым и возвращается полный список.

### US-L2. Отличить отсутствие совпадений от ошибки (P1)

- **Given** существуют подписчики, **When** корректный запрос не находит совпадений, **Then** сервер возвращает `200`, `items: []`, `total: 0`.
- **Given** хранилище пусто, **When** выполняется запрос без фильтра, **Then** это также успешный пустой ответ, а не ошибка сервера.

### US-L3. Получить предсказуемый отказ на неверный вход (P1)

- **Given** запрос после `strip()` содержит ровно 100 Unicode code points, **When** он передан серверу, **Then** длина допустима.
- **Given** запрос после `strip()` содержит 101 code point, **When** он передан серверу, **Then** ответ `400` содержит `error.code: "query_too_long"`.
- **Given** повторяется `q`, передан неизвестный параметр или query string содержит некорректную UTF-8 последовательность, **When** сервер разбирает запрос, **Then** ответ `400` содержит `error.code: "invalid_query"`.
- **Given** предыдущий запрос завершился `400`, **When** приходит корректный поиск, **Then** сервер продолжает работу и возвращает обычный ответ.

### US-L4. Сохранить старые операции (P1)

- **Given** добавлен `Alice`, **When** выполняется поиск и вызывающий изменяет полученный список, **Then** множество подписчиков не меняется.
- **Given** добавлен `Alice`, **When** вызывается `unsubscribe(" Alice ")`, затем `unsubscribe("Alice")`, **Then** результаты соответственно `True` и `False`.
- **Given** пустое имя, **When** его передают в существующую подписку или отписку, **Then** сохраняется прежний `ValueError`.
- **Given** точное одинаковое имя добавлено дважды, **When** читается список, **Then** дубликат отсутствует.

### US-L5. Воспроизводимо показать фичу (P2)

- **Given** новый процесс без `--demo`, **When** выполняется первый запрос, **Then** хранилище пустое.
- **Given** новый процесс с `--demo`, **When** он запускается, **Then** через существующий `subscribe` добавлены только `Alice`, `Bob`, `Анна`, `Борис`.

## Requirements

### Функциональные требования

- **L-FR-001:** хранить подписчиков в существующем `set` в памяти; сохранить поведение `subscribe`, `unsubscribe`, `list_subscribers`.
- **L-FR-002:** предоставить поиск через `GET /api/subscribers?q=<URL-encoded query>`; допускается отсутствие `q`, но не его повторение и не неизвестные параметры.
- **L-FR-003:** нормализовать вход на сервере через Python `str.strip()`; внутренние пробелы сохранять. UI не является источником правил Unicode-нормализации или допустимой длины.
- **L-FR-004:** проверять длину нормализованного запроса до `casefold()`: от 0 до 100 Unicode code points включительно. Это не байты UTF-8 и не количество UTF-16 code units JavaScript.
- **L-FR-005:** искать подстроку через Unicode `casefold()` для запроса и имени. `е` и `ё` различаются; NFC-нормализация, транслитерация и нечёткий поиск не выполняются.
- **L-FR-006:** возвращать новый список имён в порядке прежнего `list_subscribers()`; не менять данные, регистр или правила уникальности исходного хранилища.
- **L-FR-007:** возвращать успешный JSON с полями `query: string`, `items: string[]`, `total: integer`; `query` содержит результат `strip()` с сохранённым регистром, `total == len(items)`.
- **L-FR-008:** пустой запрос возвращает всех; отсутствие совпадений и пустое хранилище дают успешный пустой результат.
- **L-FR-009:** отдавать страницу и API с одного origin; данные JSON имеют `Content-Type: application/json; charset=utf-8`.
- **L-FR-010:** предоставлять воспроизводимое наполнение только по явному флагу `--demo`; перезапуск не сохраняет изменения в памяти.

### Общий HTTP-контракт

Успешный ответ:

```json
{"query":"ALI","items":["Alice"],"total":1}
```

Ошибка длины:

```json
{"error":{"code":"query_too_long","message":"Поисковый запрос должен быть не длиннее 100 символов."}}
```

| HTTP | `error.code` | Условие |
|---|---|---|
| 400 | `query_too_long` | После `strip()` больше 100 code points |
| 400 | `invalid_query` | Повторный/неизвестный параметр либо некорректная UTF-8 query string |
| 404 | `not_found` | Неизвестный маршрут |
| 405 | `method_not_allowed` | POST/PUT/PATCH/DELETE к поисковому API |

UI отображает `error.message` ответа `400` как текст. Сеть, `5xx` и неверная форма JSON обрабатываются UI общим сообщением с повтором. Логика не должна использовать текст ошибки вместо стабильного `error.code`. Неожиданные внутренние исключения не должны раскрывать traceback пользователю; отдельная гарантированная JSON-схема `500` в v1 не добавляется сверх общего контракта.

### Совместимость с UI

- Начальная загрузка и сброс соответствуют одному запросу без фильтра.
- Backend определяет сортировку и сравнение; UI отображает полученный порядок.
- Ограничение в 100 code points проверяется сервером, поэтому поле UI не должно вводить другой лимит через JavaScript `length` или HTML `maxlength`.
- Сервер формирует независимые ответы запросов; выбор последнего актуального ответа и предотвращение перезаписи новым/старым запросом относятся к UI.
- Имена могут содержать HTML-подобный текст: API передаёт их строками JSON, а UI обязан отображать как текст.

### Границы

Python standard library, один origin, хранилище в памяти. Без БД, авторизации, пагинации, CRUD по HTTP, автопоиска при каждом символе и изменения старых функций. Фича рассчитана на небольшой учебный каталог; линейный поиск с сортировкой достаточен.

## Success Criteria

1. **L-SC-001:** unit- и HTTP-проверки подтверждают Latin/Cyrillic поиск, серверный trim, полный/пустой результат и соответствие `total` длине массива.
2. **L-SC-002:** 100 code points принимаются, 101 возвращает `400 query_too_long`; проверяется пример с символами вне BMP, чтобы не спутать code points с UTF-16 code units.
3. **L-SC-003:** повторные/неизвестные параметры и ошибочная UTF-8 последовательность дают `400 invalid_query`; корректный запрос после ошибки успешно обрабатывается.
4. **L-SC-004:** регрессионные проверки исходных функций проходят; поиск и изменение возвращённого списка не меняют исходный `set`.
5. **L-SC-005:** сквозной сценарий с `--demo` подтверждает путь UI → API → поиск → UI и восстановление после ошибки, а запуск без флага не создаёт демонстрационные записи.

Это критерии будущей проверки. Фактические команды, результаты и принятие человеком будут фиксироваться после реализации.

## Изменения после сверки двух команд

| Было в независимой версии логики | Стало в общей редакции | Причина |
|---|---|---|
| 128 символов после trim | 100 Unicode code points после серверного `strip()` | Единый предел с UI, без расхождения единиц длины |
| Общая `invalid_query` для превышения длины | Специальная `query_too_long` | UI различает валидационную ошибку длины |
| Открытый вопрос об общем числе подписчиков | Только число совпадений, `total == len(items)` | Убирается двусмысленность счётчика |
| Политика неизвестных параметров обсуждалась | Неизвестные и повторные параметры отклоняются | Стабильный общий контракт v1 |
| Предлагалась отдельная гарантированная JSON-ошибка `500` | Не добавляется к общему контракту | UI уже обрабатывает любой `5xx` как общую ошибку |

Оставшихся блокирующих противоречий общему контракту не обнаружено. Конкретный выбор HTTP-сервера и способ упаковки кода относятся к реализации и не меняют договорённое поведение. Редакция и общий контракт утверждены пользователем до реализации; см. evidence/human-approval.json.
