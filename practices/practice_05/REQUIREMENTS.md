# Практика 5: требования к домашней работе

Источник — последний слайд `prenetation.pdf`, полученный из репозитория курса
`upstream/main`, коммит `ed72ed8`. Дата получения: 2026-10-26.

Домашнее задание отличается от упражнений с OpenSpec на предыдущих слайдах:
нужно применить другой SDD-фреймворк к одной фиче существующего проекта.

| Критерий | Баллы | Планируемый артефакт |
|---|---:|---|
| Другой SDD-фреймворк: применение и сравнение с OpenSpec | 2 | Spec Kit, `.specify/`, `FRAMEWORK.md`, спецификация, план, задачи |
| Две спецификации, согласованные до кода | 2 | Независимые `specs/before/ui.md` и `logic.md`, обновлённые спецификации, общий контракт, решение пользователя |
| Работающие UI и логика, сквозная проверка и ошибка/граница | 5 | Приложение, тесты, реальные результаты и демонстрация |
| Рефлексия | 1 | `reflection.md` с наблюдениями о согласовании |

Две команды эмулируются двумя независимыми агентами. Пользователь одобрил этот
способ и фичу поиска подписчиков до начала подготовки согласованного решения.
Одобрение общей идеи не подменяет согласование конкретного API-контракта.

Границы: продолжаем существующий сервис подписок из практики 4. Добавляем поиск
по списку в веб-интерфейсе; исходные функции подписки, отписки и получения списка
сохраняются. База данных, авторизация, CRUD через HTTP и внешние UI-библиотеки
не входят в эту фичу.

Порядок: исходные спецификации → согласованный контракт и обновлённые спеки →
решение человека → реализация → независимая проверка и демо.
