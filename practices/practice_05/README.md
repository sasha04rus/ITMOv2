# Практика 5: две команды, одна фича

Поиск подписчиков в веб-интерфейсе существующего сервиса. SDD-фреймворк —
GitHub Spec Kit. Один origin, Python standard library, HTML/CSS/JavaScript без сборки.

## Запуск

Из этой папки в WSL/Linux с Python 3.10+:

```bash
python3 -m app.server --demo
```

Откройте **http://127.0.0.1:8765**. Для другого порта добавьте `--port 8766`.
В Windows с доступным Python команда аналогична: `python -m app.server --demo`.
Без `--demo` список пустой. Данные хранятся только в памяти процесса.

## Демо на одну минуту

1. Откройте страницу: четыре имени Alice, Bob, Анна, Борис.
2. Введите `  ALI  ` и нажмите «Найти»: останется Alice.
3. Введите `АН` и нажмите Enter: останется Анна.
4. Введите `zzz`: «Ничего не найдено» — это успешный пустой ответ.
5. Нажмите «Сбросить»: весь список вернётся, поле очистится и получит фокус.
6. Отправьте 101 символ: сервер вернёт понятную ошибку; исправьте строку и найдите имя.

Исходные операции subscribe/unsubscribe/list_subscribers сохранены, но HTTP CRUD
в фичу не входит. UI только ищет и не меняет подписки.

## Проверки

```bash
python3 -m unittest discover -s tests -v
python3 scripts/check_spec.py
```

Либо `make test` и `make spec-check`. Корневой Makefile курса не включает эту
домашнюю работу: команды выполняются в папке `practices/practice_05`.

Для браузерных тестов дополнительно нужны Node.js и Playwright:

```bash
npm install
npx playwright install chromium
npm run test:e2e
```

На машине с установленным Edge можно использовать его без скачивания Chromium:

```powershell
$env:PRACTICE05_BROWSER_CHANNEL = 'msedge'
npm run test:e2e
```

Если установленный Edge закрывается при обычном запуске Playwright, проверенный
на этой машине вариант использует отдельный headless-профиль и локальный CDP:

```powershell
python scripts/edge_e2e.py
```

Это вспомогательный запуск браузерных тестов, а не зависимость приложения.

При нестандартном пути Python задайте `PRACTICE05_PYTHON`.
`PLAYWRIGHT_MODULE` позволяет использовать уже установленный модуль Playwright.
E2E сам запускает отдельный сервер на свободном порту и завершает его после тестов.

## Как устроена фича

Форма → GET `/api/subscribers?q=...` → нормализация через `strip`, проверка длины,
поиск подстроки через `casefold` → новый отсортированный список → отображение UI.
Лимит — 100 Unicode code points после нормализации, а не 100 байтов или UTF-16 units.
Полный контракт: `specs/001-subscriber-search/contracts/http.md`.

Исходный сервис взят из зафиксированной версии практики 4; ссылка и SHA-256
исходных файлов находятся в `evidence/baseline.json`. Остальные практики не менялись.
