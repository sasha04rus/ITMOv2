## Статический анализ по контракту

| Требование | Найденная реализация | Вывод статического анализа |
|---|---|---|
| Начальная загрузка полного списка | В конце `app.js` вызывается `search("")`; пустой запрос не добавляет `q` | Соответствует |
| Enter и кнопка поиска | Оба используют событие `submit` формы и `search(input.value)` | Соответствует; запрос не отправляется на каждый символ |
| Same-origin и единственный параметр | URL создаётся от `window.location.origin`, единственный добавляемый параметр - `q` через `URL.searchParams` | Соответствует |
| Серверная нормализация и Unicode-граница | В запрос идёт исходный `input.value`; нет клиентского `trim`, проверки длины или HTML `maxlength` | Не возникает второй трактовки границы в UTF-16; фактические 100/101 code points должен проверить E2E |
| Состояния loading/success/empty/error | `setState` обновляет `data-state`, статус, видимость списка, счётчика и повтора; очищает прежние элементы | Соответствует: прошлые результаты не выдаются за новый ответ |
| Проверка успешного ответа | `isSearchResponse` проверяет объект, строку `query`, массив строк `items`, неотрицательный safe integer `total` и равенство длине массива | Соответствует; некорректная форма не показывается как успешный пустой список |
| Порядок и исходные имена | `showResponse` перебирает `data.items` без дополнительной фильтрации и сортировки; полное имя идёт в `label.textContent` | Соответствует. Изменение регистра применяется только к декоративной первой букве аватара |
| HTTP 400 | Только при корректной форме `error.code`/`error.message` показывается `error.message` | Соответствует; текст ошибки не интерпретируется как HTML |
| HTTP 5xx, 404/405 и другие неожиданные ответы | Все ответы, не попавшие в ветку валидного 200/400, приводят к общему сообщению и состоянию error | Соответствует |
| Некорректный JSON | Исключение `response.json()` попадает в `catch`; неверная форма объекта попадает в общую ветку ошибки | Соответствует |
| Сетевая ошибка | `catch` показывает общую ошибку для актуального запроса | Соответствует |
| Устаревший ответ и отмена | Каждому запросу присваивается растущий `requestId`; предыдущий controller отменяется; актуальность проверяется после fetch, после JSON и в catch | Старый успех/ошибка не должны перезаписать новое состояние; поведение требует браузерного теста с задержками |
| Повтор последнего отправленного запроса | `lastSubmittedQuery` обновляется при отправке; retry вызывает `search(lastSubmittedQuery)`, а не читает поле | Соответствует даже при последующем изменении текста поля |
| Сброс и фокус | Обработчик очищает `input.value`, вызывает `input.focus()` и `search("")` | Соответствует; сброс становится новым приоритетным запросом |
| Безопасный DOM | Имена, применённый запрос, счётчик и сообщения выводятся через `textContent`; строки не передаются в `innerHTML` | HTML-подобные значения обрабатываются как данные |
| Доступность | Label связан с полем; форма использует нативные кнопки; статус имеет `role="status"`, `aria-live="polite"`, `aria-atomic="true"` | Соответствует на уровне разметки; работу assistive technology не проверяли |
| CSS и скрытые состояния | `[hidden] { display: none !important; }`; присутствуют стили состояний, клавиатурного фокуса и media queries | Код предусматривает видимость и адаптацию; визуальную корректность должен подтвердить браузер |
